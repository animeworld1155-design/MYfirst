# Cross-check agent

A second, independent agent that audits the submission in `hackrank/` **from the
outside**. It lives in this folder (outside the challenge repository) so it can
never become part of `code.zip`, and it never writes into `hackrank/`: it reads
the deliverables, re-derives every check from the raw participant-facing files
with its own code, and writes its report next to itself.

It exists because a bug in the auditor under test must not be able to hide
itself: the contract, the time rule, the evidence grounding, the intake decision
and the sample score are all recomputed here rather than imported from
`hackrank/code`.

## Run

```bash
python3 crosscheck_agent/agent.py            # full report
python3 crosscheck_agent/agent.py --quiet    # one-line summary
python3 crosscheck_agent/agent.py --report /tmp/report.md
```

Python 3.10+, standard library only, no network, no keys. Exit code is `1` when
a hard check fails, `0` otherwise.

## What it checks

| # | Check | Severity | What it proves |
| --- | --- | --- | --- |
| 1 | Contract | hard | `output.csv` has the exact header, 518 unique rows sorted by `case_id`, every `steps_json` parses, step numbers are consecutive, phases run FINDING → REMEDIATION → VERIFICATION, steps are in the required operation/system/resource order, only the 15 allowed operations and 7 allowed states appear, findings cite evidence, remediation and INCOMPLETE verification do not, COMPLETE verification does, `NOT_APPLICABLE` rows are `[]` |
| 2 | Time | hard | every cited `file_id` exists and was captured **at or before** the case's `audit_at` — evidence from the future cannot prove the audited moment |
| 3 | Grounding | hard/soft | a cited resource id must occur inside the cited text file; steps whose state is `ABSENT` are counted separately as *absence proofs* (there the id is expected to be missing, because the capture enumerated the system without it); binary evidence (PDF/PNG) is reported as not text-checkable instead of failed |
| 4 | Intake | soft | an independently written deletion-intake classifier (its own marker set, deliberately phrased differently from the auditor's) is compared with the COMPLETE/INCOMPLETE vs `NOT_APPLICABLE` verdicts |
| 5 | Sample | informational | when `hackrank/sample_prediction.csv` exists it is scored against `dataset/sample_output.csv` with an independent scorer: status accuracy, exact sequence, micro/macro step F1, state and evidence accuracy |
